# Архитектура

ЦДС собирает презентацию по брифу в корпоративном шаблоне пользователя. На вход — от одного до трёх шаблонов
`.pptx`/`.potx`, картинки (необязательно) и промпт. На выходе — по колоде на каждый шаблон в трёх вариантах
вёрстки, в форматах `.pptx` (нативные объекты), `.pdf` и `.html`, с аудитом и исправлениями.

```
 браузер (React-конфигуратор)                                       docker compose
 ─────────────────────────────                                      ──────────────
  шаблоны, картинки, промпт ──POST──►  backend  (FastAPI + LangGraph, LibreOffice)     :8000
  прогресс ◄──────────── SSE ────────   │   ├── MCP web   (поиск, чтение страниц) ──► SearXNG
  превью, аудит, файлы ◄─ GET/POST ──   │   └── MCP pptx  (осмотр, аудит, правка, рендер)
                                        └── OpenAI-совместимый провайдер модели (один, из .env)
```

## Слои и их границы

Модель работает только там, где нужен смысл. Всё, что можно посчитать, считается кодом и детерминировано:
один и тот же вход даёт один и тот же файл.

| Слой | Где | Модель | Что делает |
|---|---|---|---|
| **Парсинг** | `prism/parsing` | классификация слайдов | разбирает шаблон в `TemplateSpec`: токены дизайн-системы и образцы слайдов |
| **Генерация** | `prism/generation`, `prism/planning` | да | поиск материалов, план колоды, тексты слайдов с проверками полноты |
| **Вёрстка** | `prism/layout` | нет | выбор образца под каждый слайд, раскладка по слотам, подгонка текста, свои композиции, диаграммы и таблицы |
| **Рендер** | `prism/render.py` | нет | LibreOffice → PDF → PNG-превью |
| **Аудит** | `prism/audit` | смысловая часть | детерминированные и смысловые проверки, исправления — подробно в [AUDIT.md](AUDIT.md) |
| **Экспорт** | `prism/export`, рендер | нет | `.pptx` (сама колода), `.pdf`, `.html` |
| **API / UI** | `backend/app`, `frontend` | — | задачи, SSE-прогресс, аккаунты, панель аудита |

### Парсинг шаблона

`extract` → `tokens` → `patterns` → `classify` → `TemplateSpec`, кеш в `data/specs/<sha>/`.

- **extract** — всё, что есть в файле: абсолютные координаты (через вложенные группы), наследование стилей
  слайд → макет → мастер → тема, цвета темы (`schemeClr` → `clrMap` → hex с модификаторами), плейсхолдеры,
  направляющие, картинки (средний цвет, прозрачность, «детальность» для рисунков в фоне).
- **tokens** — дизайн-система:
  - палитра с ролями (фон, текст, акцент, подложка);
  - пары «текст на фоне»;
  - шкала кеглей с ролями (display / title / heading / body / caption);
  - шрифты;
  - поля, привязанные к направляющим;
  - варианты фона.
- **patterns** — композиционные образцы:
  - слоты (заголовок, текст, число, картинка, график, таблица);
  - повторяющиеся группы карточек/шагов: ищутся по «дорожкам» одинаковых фигур с постоянным сдвигом, по подложкам колонок и по шагу сетки;
  - «таблетки» под заголовком, декор, безопасная рамка заголовка;
  - карточки, нарисованные в макете или прямо в фоновой картинке (их число менять нельзя).
- **classify** — тип каждого образца (title, cards, kpi, timeline, chart, …). Сначала эвристики, затем скилл
  `template_classifier`: он же отделяет служебные слайды (инструкции к шаблону) и библиотеки иконок.

Шаблон задаёт **только стиль**: его тексты и цифры в колоду не попадают.

### Генерация (граф LangGraph)

```
research ──► plan ──► write ──► compose ──► render ──► audit
```

| Узел | Что делает |
|---|---|
| `research` | Только для короткого брифа без цифр. Скилл `researcher` пишет запросы → MCP `web_search` (SearXNG) → MCP `fetch_page` → скилл `research_digest` выбирает факты с источником. Бюджет — 60 с |
| `plan` | Три плана параллельно, по одному на вариант (`configs/variants.yaml`): состав, порядок и тип слайдов. Доступные типы — те, что есть в загруженных шаблонах, плюс те, что вёрстка соберёт сама |
| `write` | Тексты пачками по 4 слайда, все варианты параллельно. Затем `checks.content_problems` (полнота по типу, длины, данные графика, служебные пометки модели), один круг исправления моделью и понижение типа, если слайд так и не стал полным |
| `compose` | Шаблон × вариант, параллельно в потоках |
| `render` | Общий пул LibreOffice на все колоды; PDF, PNG-превью, HTML |
| `audit` | Детерминированный аудит всех колод, `context.json` для смыслового аудита |

Прогресс идёт custom-событиями графа → SSE → анимация генерации в интерфейсе. Время: 9 колод
(3 шаблона × 3 варианта) — 2–3 минуты, из них поиск в интернете — 10–20 с.

### Вёрстка

Для каждого слайда оцениваются все образцы шаблона (`compose.choose_pattern`):
- совпадение типа;
- число карточек против числа пунктов;
- покрытие полей (число, заголовок, пояснение);
- вместимость текста;
- место под график;
- поля-заглушки, которым нечего дать;
- разнообразие.

Слайд-образец клонируется, текст встаёт в слоты с сохранением оформления абзацев. Кегль подгоняется по
ступеням шкалы шаблона (метрики настоящих шрифтов, `fit.py`). Лишние карточки убираются вместе с их иконками
и подложками. Если достойного образца нет или варианту нужна другая подача, слайд собирается «своей
композицией» (`synth.py`): это холст-образец шаблона без контента плюс нативные блоки только из палитры,
шрифтов, шкалы и полей шаблона. Диаграммы и таблицы — нативные объекты PowerPoint.

**Три варианта** отличаются по оси «плотность и способ подачи»:

| Вариант | Слайдов | Подача |
|---|---|---|
| «Сбалансированный» | 11–13 | лучший образец под каждый слайд |
| «Визуальный» | 12–14 | числа — крупно или в графиках, короткие тексты, акцентные разделители, свои композиции |
| «Компактный» | 10 | темы объединены, таблицы и сравнения, без разделителей; другие образцы, чем в первом варианте |

Различаются и план, и тексты, и вёрстка. Все три — по правилам одного шаблона.

### Аудит и исправления

Детерминированные проверки — часть графа. Смысловые (модель по картинке слайда) и исправления запускаются
из панели аудита и дают новую ревизию колоды. Подробно — [AUDIT.md](AUDIT.md).

### Экспорт

- **`.pptx`** — сама колода: слайды-клоны шаблона, текст, фигуры, диаграммы и таблицы — нативные объекты.
- **`.pdf`** — LibreOffice из того же `.pptx`.
- **`.html`** (`prism/export/html.py`) — самодостаточный файл:
  - фигуры — абсолютно позиционированные элементы, текст — настоящий текст с кеглем в долях ширины слайда (`cqw`);
  - картинки встроены один раз;
  - таблицы — `<table>`, диаграммы — SVG по данным `.pptx`;
  - режим показа по F и стрелкам.

## Модели, скиллы, конфиги

- **Провайдер один** — OpenAI-совместимый API из `backend/.env` (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`,
  `LLM_VISION_MODEL`, `LLM_API_STYLE`). Смена провайдера или модели — только правка `.env`.
- **Роли** (`configs/default.yaml`) — узлы обращаются к роли, у роли свои температура, режим размышлений,
  лимит токенов и слот модели (text/vision). Какие модели и почему — [MODELS.md](MODELS.md).
- **Скиллы** (`backend/skills/<имя>/v<N>.yaml`) — промпты отдельными файлами с версиями: system и user (Jinja2),
  привязка к роли. Версии закрепляются в `skills:` конфига; в `manifest` каждого запуска пишутся `имя@vN` и sha256.

| Скилл | Роль | Где используется |
|---|---|---|
| `template_classifier` | template_classifier | разметка образцов шаблона |
| `researcher`, `research_digest` | research | поиск материалов для короткого брифа |
| `outline_planner` | outline_planner | план колоды по варианту |
| `slide_writer` | slide_writer | тексты слайдов |
| `slide_auditor` | audit_vlm | смысловой аудит слайда по картинке |
| `deck_auditor` | fix_agent | связность колоды |
| `text_shortener` | shorten | исправление «не помещается / слишком длинно» |
| `slide_fixer` | fix_agent | исправление смысловых замечаний |

- **Структурированный вывод** (`llm/structured.py`):
  - JSON Schema в `response_format`; если провайдер его не принимает — схема в тексте запроса;
  - ошибка валидации возвращается модели на исправление;
  - оборванный ответ — повтор с просьбой «компактно»;
  - отказ по ключу (401/402/403) сразу останавливает генерацию понятным сообщением.

## MCP

Два своих MCP-сервера (streamable HTTP, `mcp` SDK), подключаются к графу через `langchain-mcp-adapters`
(`prism/mcp/client.py`):

- **web** (`prism/mcp/web_server.py`):
  - `web_search` — выдача self-hosted SearXNG;
  - `fetch_page` — основной текст страницы (trafilatura). Во внутреннюю сеть не ходит, в том числе на редиректах.
- **pptx** (`prism/mcp/pptx_server.py`) — `template_summary`, `inspect_deck`, `audit_deck`, `render_slide`,
  `set_shape_text`. Файлы — только внутри каталога данных.

Проверка: `GET /api/health/mcp` — список инструментов каждого сервера и пробный поиск через SearXNG.

## Данные

```
backend/data/
  prism.db                     аккаунты, сессии, шаблоны и колоды пользователей (SQLite)
  uploads/<tid>.pptx           загруженные шаблоны
  specs/<tid>/spec.json        разбор шаблона (кеш по sha256 и версии разбора)
  images/                      картинки пользователей
  decks/<id>/
    request.json, context.json, result.json
    <tid>/v<N>/deck.pptx, deck.pdf, deck.html, preview/slide-NN.png,
               report.json (вёрстка), audit.json (аудит), deck.orig.pptx (до исправлений)
```

## Развёртывание

`docker compose up -d --build` из корня:

| Сервис | Наружу | Что внутри |
|---|---|---|
| `backend` | `:8000` | API, фронтенд, LibreOffice, шрифты шаблонов |
| `mcp-web` | нет | MCP-сервер поиска |
| `mcp-pptx` | нет | MCP-сервер pptx |
| `searxng` | нет | self-hosted метапоисковик |

`backend`, `mcp-web` и `mcp-pptx` — один образ с разными командами; данные — в томе `prism-data`. Переменные — `backend/.env`
(см. [backend/README.md](backend/README.md)).
