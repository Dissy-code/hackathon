# ЦДС — цифровой дизайнер презентаций

Кейс VK Tech. Сервис собирает презентацию по брифу в корпоративном шаблоне пользователя:
разбирает шаблон (дизайн-токены, композиционные образцы), при коротком брифе сам ищет материалы в интернете,
пишет структуру и текст, верстает слайды по правилам шаблона в трёх вариантах, проверяет результат аудитом
и выгружает в `.pptx` (нативные объекты), `.pdf` и `.html`.

**Документация:**
- [ARCHITECTURE.md](ARCHITECTURE.md) — пайплайн и границы слоёв;
- [MODELS.md](MODELS.md) — модели, роли, системные требования;
- [AUDIT.md](AUDIT.md) — проверки и их покрытие;
- [backend/README.md](backend/README.md) — разработка.

## Что умеет

| | |
|---|---|
| **Вход** | 1–3 шаблона `.pptx`/`.potx`, картинки (необязательно), промпт — подробный бриф или одна строка («рынок электросамокатов в России») |
| **Шаблон** | задаёт только стиль: палитру, шрифты, шкалу кеглей, поля, образцы слайдов. Его тексты и цифры в колоду не попадают |
| **Короткий бриф** | модель ищет факты через self-hosted SearXNG, читает страницы и берёт цифры только из них |
| **Выход** | по колоде на каждый шаблон × 3 варианта (сбалансированный, визуальный, компактный); 10–15 слайдов или столько, сколько задано |
| **Слайды** | титул, разделители, карточки, KPI, процессы и таймлайны, сравнения, цитаты, нативные диаграммы и таблицы, картинки пользователя |
| **Аудит** | детерминированные проверки — сразу после генерации; смысловая проверка моделью по картинкам слайдов — по кнопке; исправления на выбор пользователя |
| **Экспорт** | `.pptx` (редактируемые объекты), `.pdf`, `.html` (живой текст, SVG-диаграммы, режим показа) |
| **Аккаунты** | регистрация по e-mail и паролю, сессии, счётчики шаблонов и колод |

Генерация 9 колод (3 шаблона × 3 варианта) занимает 2–3 минуты.

## Быстрый старт

Нужны Docker с плагином compose и ключ OpenAI-совместимого провайдера модели.

```bash
git clone <репозиторий> cds && cd cds
cp backend/.env.example backend/.env      # вписать LLM_BASE_URL, LLM_API_KEY, LLM_MODEL, LLM_API_STYLE
docker compose up -d --build
```

Откройте http://localhost:8000, зарегистрируйтесь, в «Редакторе» добавьте шаблоны и опишите задачу, нажмите
«Сгенерировать». В «Демонстрации» доступны:
- переключение шаблонов и вариантов;
- кнопка «Аудит»;
- скачивание PPTX, PDF и HTML.

Проверка, что всё поднялось:

```bash
curl localhost:8000/api/health        # модель, скиллы, "mcp": ["pptx", "web"]
curl localhost:8000/api/health/mcp    # инструменты MCP-серверов и пробный поиск через SearXNG
```

### Сервисы docker compose

| Сервис | Что делает | Порт наружу |
|---|---|---|
| `backend` | API (FastAPI + LangGraph), фронтенд, рендер LibreOffice | `8000` |
| `mcp-web` | MCP-сервер поиска: `web_search` (SearXNG), `fetch_page` | нет |
| `mcp-pptx` | MCP-сервер pptx: осмотр, аудит, рендер, правка слайдов | нет |
| `searxng` | self-hosted метапоисковик | нет |
| `caddy` | HTTPS-прокси, только с `--profile https` | `80`, `443` |

Данные — шаблоны, колоды, база аккаунтов — лежат в томе `prism-data`.

### Сервер (VDS)

Рекомендуется 4 vCPU, 8 ГБ RAM, 20 ГБ диска, Ubuntu 22.04/24.04.

Корневой `.env` (переменные для docker compose; пример — [.env.example](.env.example)):

```bash
PRISM_BIND=127.0.0.1           # backend только на localhost — наружу через прокси
COOKIE_SECURE=1                # cookie сессии — только по HTTPS
SEARXNG_SECRET=<случайная строка>
DOMAIN=cds.example.ru          # только для варианта с Caddy
```

Прокси — любой из двух:
- **Caddy** — сертификат выпускается сам: `docker compose --profile https up -d --build`.
- **nginx** — конфиг [deploy/nginx/cds.conf](deploy/nginx/cds.conf), сертификат через certbot. В конфиге отключена
  буферизация для прогресса генерации (SSE) и увеличены таймауты.

Снаружи открыть только 22, 80 и 443.

### Без Docker (разработка)

Python 3.12+, Node 22, LibreOffice (`soffice`), poppler (`pdftoppm`):

```bash
cd backend && python -m venv venv && . venv/bin/activate && pip install -e ".[dev]"
cp .env.example .env && scripts/install_fonts.sh
(cd ../frontend && npm ci && npm run build)
uvicorn app.main:app --reload           # http://localhost:8000
```

Поиск в интернете без Docker требует запущенных SearXNG и `mcp-web` — см. [backend/README.md](backend/README.md).
Без них короткий бриф генерируется без материалов, с предупреждением.

## Переменные окружения

### `backend/.env` — сервис

| Переменная | Обязательна | Назначение |
|---|---|---|
| `LLM_BASE_URL` | да | OpenAI-совместимый API провайдера модели (vLLM, llama.cpp, Open WebUI — `…/api`, облачный шлюз) |
| `LLM_API_KEY` | да | ключ провайдера |
| `LLM_MODEL` | да | модель для текста |
| `LLM_VISION_MODEL` | нет | модель для картинок (смысловой аудит); пусто — та же, что `LLM_MODEL` (должна быть мультимодальной) |
| `LLM_API_STYLE` | нет | как передавать нестандартные параметры: `vllm` (по умолчанию) / `openrouter` / `plain` |
| `LLM_FAKE` | нет | `1` — демо-режим без модели: подставной текст, настоящие вёрстка, рендер и аудит |
| `MCP_WEB_URL` | нет | MCP-сервер поиска; в compose задаётся сам. Пусто — без поиска в интернете |
| `MCP_PPTX_URL` | нет | MCP-сервер pptx; в compose задаётся сам |

### Корневой `.env` — docker compose

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PRISM_PORT` | `8000` | порт backend на хосте |
| `PRISM_BIND` | `0.0.0.0` | адрес, на котором слушает backend; за прокси — `127.0.0.1` |
| `COOKIE_SECURE` | `0` | `1` — cookie сессии только по HTTPS |
| `SEARXNG_SECRET` | тестовое значение | секрет SearXNG — на сервере задать свой |
| `DOMAIN` | `localhost` | домен для Caddy (`--profile https`) |

### Прочее, для тонкой настройки

| Переменная | Где | Назначение |
|---|---|---|
| `SEARXNG_URL` | mcp-web | адрес SearXNG (в compose — `http://searxng:8080`) |
| `FETCH_ALLOW_NETS` | mcp-web | сети, которые `fetch_page` не считает внутренними; по умолчанию `198.18.0.0/15` — адреса DNS у прокси и VPN-роутеров в режиме fake-IP |
| `PRISM_DATA_DIR` | mcp-pptx | каталог, за пределы которого инструменты pptx не выходят |
| `MCP_HOST`, `MCP_PORT` | mcp-web, mcp-pptx | адрес и порт MCP-сервера |

Параметры модели по ролям (температура, режим размышлений, лимиты токенов), бюджет поиска и версии скиллов
задаются в [backend/configs/default.yaml](backend/configs/default.yaml). Варианты колоды — в
[backend/configs/variants.yaml](backend/configs/variants.yaml). Промпты — в `backend/skills/<имя>/v<N>.yaml`.

## Ограничения

**Шаблоны**
- Принимаются только `.pptx` и `.potx`. PDF и HTML не годятся как шаблон: из них не восстановить макеты, стили и плейсхолдеры.
- В шаблоне должны быть слайды-образцы. Шаблон, где есть только макеты без заполненных слайдов, пока не поддерживается: образцы строятся из слайдов.
- Шрифты, которые шаблон использует, но не встраивает, должны быть установлены на сервере. Для шаблонов из датасета их ставит `scripts/install_fonts.sh`. Иначе LibreOffice подменяет шрифт в PDF и превью, а подгонка текста расходится с PowerPoint.

**Генерация**
- Провайдер модели — один. Качество текста и смыслового аудита зависит от модели. Для смыслового аудита модель должна понимать картинки.
- Поиск включается, только если бриф короткий и почти без чисел. Ему нужен доступ в интернет. С IP дата-центра поисковики иногда ограничивают выдачу; тогда колода собирается по брифу, с предупреждением.
- Цифры в колоде берутся только из брифа и найденных материалов. Если данных нет, слайд пишется качественно, без выдуманных чисел.
- Диаграммы — столбцы, полосы, линия, круг, кольцо (до 5 серий). SmartArt не создаётся: процессы, циклы и таймлайны собираются из нативных фигур шаблона или своими композициями на его токенах.
- Иконки и иллюстрации берутся только из самого шаблона. Новые картинки не генерируются.
- Языки — русский и английский.

**Время**
- 3 шаблона × 3 варианта — 2–3 минуты. Поиск добавляет до минуты (бюджет 60 с).
- Смысловой аудит (около 20 с на колоду) и исправления моделью в эти 5 минут не входят: их запускает пользователь.

**Экспорт**
- `.html` передаёт текст, фигуры, картинки, таблицы и диаграммы, но без теней, эффектов и градиентов (берётся первый цвет). Фигуры сложной формы рисуются прямоугольником или овалом. Эталон вида — PDF.

**Эксплуатация**
- Задачи генерации живут в памяти процесса: при перезапуске идущая генерация теряется. Готовые колоды лежат на диске и открываются по ссылке `/configurator.html?deck=<id>`.
- Колода доступна любому, у кого есть её id. Список колод в аккаунте пока не выводится — только счётчик.
- Интерфейс рассчитан на десктоп (по ТЗ). Мобильные устройства не поддерживаются.

## Структура репозитория

```
backend/            сервис: FastAPI (app/), пайплайн и вёрстка (prism/), промпты (skills/), конфиги, тесты
  prism/parsing     разбор шаблона: извлечение, токены, образцы, классификация
  prism/generation  граф LangGraph: поиск, план, тексты, вёрстка, рендер, аудит
  prism/layout      вёрстка по образцам и свои композиции
  prism/audit       проверки и исправления
  prism/export      экспорт в HTML
  prism/mcp         MCP-серверы web и pptx, клиент
frontend/           интерфейс: React-конфигуратор (Configurator.tsx, AuditPanel.tsx), вход, главная
deploy/             SearXNG, Caddy, nginx
docker-compose.yml
```

Тесты: `cd backend && pytest` (без сети). Тесты с реальной моделью — `pytest -m live`.
